# NQ 미래 검증: 실행 전후 분리와 단일 제출 시도 준비

**검증 준비의 두 결함을 확인하고 별도 코어를 구현했다. 실제 전략 검증은 여전히 미완료다.** 기존 생산 Bridge·캠페인 게이트·전략·미사용 기간은 변경하지 않았다.

## 확인한 문제와 처리

| 문제 | 처리 | 남은 작업 |
|---|---|---|
| 기존 adapter.native_result는 Standard 체결만 허용 | 고정 High/Tick/1 요청의 별도 응답 동일성 검사를 작성 | 실제 실행 후 원자료·신호·체결·위험 대조 |
| 준비 초안은 미래 signal/clock/ledger 출력까지 요구 | 실행 전 조건과 실행 후 필수 증거를 분리 | 이전 전체 증거 초안을 제출 게이트로 사용하지 않음 |
| 제출 응답 유실 때 실제 접수 여부를 알 수 없음 | 외부 호출 전 로컬 예약·제출 의도를 저장하고 두 번째 제출 거절 | 실제 생산 게이트·전송 어댑터 연결은 미완료 |
| 백테스트 ID는 엔진 재시작 후 재사용될 수 있음 | ID와 엔진 instance를 함께 묶고 관찰 | 엔진 변경 시 미해결 상태로 유지 |

이전 준비 결과를 덮어쓰지 않았다. 그 초안의 draft_prerequisites_met는 최종 증거 전체의 완결성으로 읽어야 하며, 최초 실행의 선행조건으로 사용하면 순환 조건이 된다.

## 실행 전과 실행 후

실행 전에는 고정된 10일의 완전한 품질·해시·세션/DST, 판정 시각, 원전략/설치·컴파일 동일성, 실제 NinjaTrader 데이터 반영, 결과 미리보기 없음, 현재 중지·정책 상태, 엔진 가용성과 한 번의 실행권한을 확인한다.

실행 후에는 해당 요청의 실제 체결 설정, 고정 날짜별 390봉, 원자료↔BAR↔신호, 정밀 제출/체결 시각, 거래 원장, 보유 중 Last 평가손실, 고정 비용 민감도와 최고 양의 일손익 제외 기준을 대조한다. 이를 실행 전부터 존재해야 하는 자료로 요구하지 않는다.

새 native_identity 함수는 응답 ID·엔진 instance·계획의 요청/설정·기간·시간대·완전한 원장 건수·일별 AUDIT만 확인한다. 통과해도 신호·체결·손익 정확성이 검증됐다는 뜻이 아니며 strategy_validated와 postrun_parity_complete는 false다. 비용 결과를 계산하지 않는다.

## 제출 시도 코어의 보장 범위

저장 경로·전송 인터페이스·현재 권한 확인 함수를 명시적으로 주입하는 코어다. 기본 생산 경로나 네트워크 어댑터, 실행 CLI는 제공하지 않는다. 이번 검사는 모두 임시 폴더와 가짜 어댑터로만 수행했다.

동일 계획의 로컬 예약을 호출 전에 배타적으로 기록하고 파일을 flush/fsync한다. 같은 계획으로 두 번째 제출을 시도하면 거절한다. 예약 후 실제 호출 전에 프로세스가 중단될 수도 있으므로, 서버에서 정확히 한 번 실행됐다는 보장이 아니라 **로컬 제출 시도 최대 1회**와 불확실성 보존이다. 서버 idempotency 기능이 없으므로 응답 유실 뒤 자동 재제출하지 않는다.

확인된 ID와 엔진 instance가 있을 때만 그 작업을 관찰한다. 일시적인 조회 실패를 종료로 간주하지 않는다. 재시작한 엔진의 같은 ID나 예상하지 않은 응답은 성공으로 수용하지 않는다. 실제 명시적 종료 상태를 보더라도 원 응답과 별도 연구 검증이 필요하다. 취소·삭제·대체 ID 탐색 기능은 추가하지 않았다.

첫 30개 검사 통과 뒤, 제출·조회 도중 엔진이 재시작되는 경계를 추가 검토했다. 응답 전후 instance를 다시 확인하고 변경·확인 실패 때 응답을 미확정 증거로 보존하는 회귀 검사를 추가했다. 양쪽 관찰이 같아도 서버 내부의 원자적 instance 결합을 증명한 것은 아니므로 실제 생산 연결에서 이 한계를 유지한다.

추가 검토에서 고정 시계 테스트가 가렸던 승인 시각 문제도 수정했다. 권한 확인 함수가 반환된 뒤와 외부 제출 직전에 신선도를 검사한다. 확인·저장 중 유효기간이 지나면 외부 제출 없이 submission_not_invoked로 남기며 이미 만든 예약을 복원하지 않는다. 시간이 진행되는 합성 시계로 정상 승인과 두 가지 지연 만료 경계를 확인했다.

## 이번 실제 결과

- 합성 검사 35개 통과. 실제 시장자료로 새 성과를 계산하지 않았다.
- 현재 메타데이터 평가 1회: 실행 전 미충족 18항목, 실행 후 별도 필수 증거 8항목.
- 신규 native 호출·다운로드·생산 실행 예약은 각각 0회다.
- 현재 시각은 예약 기간 시작 전이며, 판정일은 11월 7일 10:00 KST다. ready_for_native=false, 생산 어댑터 연결도 미완료다.
- 기존 원장 JSON에 포함된 과거 성과 필드는 로드되지만 이번 판정/성과 계산에 사용하지 않는다. 미래 세션 파일은 종료 전 접근하지 않는다.

## 다음에 필요한 구체 작업

CodexBollingerClock은 매일 장 마감에 그동안의 CLOCK_TRADE를 누적 출력한다. 실행 후 분석기는 반복된 누적 스냅샷의 일관성을 확인하고 정밀 entry/exit ticks로 거래 원장과 대조해야 한다. CLOCK_EXEC 이벤트 수를 누적 CLOCK_TRADE 행 수와 직접 비교하면 안 된다. 기존 감사의 고정 4거래·8체결·13일·52거래 가정을 미래 10일에 재사용하지 않는다.

정밀 시각·누적 로그 파서, 원자료/신호/원장 대조와 Last 보유 경로·비용 판독기를 별도 범위로 준비해야 한다. 자료 확보와 실제 실행 증거가 갖춰지기 전까지 채택 전략은 없다. 예약된 10세션 통과도 더 긴 사전 등록 검증 후보까지이며 Goal 완료가 아니다.
