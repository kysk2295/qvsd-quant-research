# NinjaTrader 원자료 검증 계획

기록일: 2026-10-24. 데이터 확보 전 검증 기준을 기록한다. 실전 투입 가능 후보는 아직 없다.

## 입력과 재현

- Windows에서 실제 계약월별 NQ·GC Minute/Last를 우선 확보한다. 4월은 워밍업, 5월 1일부터 확보 가능한 마지막 완료 거래일까지 평가한다. 미래 데이터는 포함하지 않는다.
- 제공사, 상품, 월물, 요청 범위와 실제 범위, UTC 변환, 봉 종료 라벨, 거래시간 템플릿, Merge policy, 행 수와 SHA-256을 기록한다.
- 원자료는 `data/incoming/`에만 저장한다. 공개 저장소에는 코드와 비식별 메타데이터 및 집계 결과만 남긴다.
- 날짜 파일명만으로 기간·완전성을 판정하지 않는다. 실제 레코드의 시각, 가격, 거래량과 세션별 누락을 검사한다. 거래소 휴장과 유지보수 시간은 누락과 구분한다.
- 동일 시각 틱을 임의로 제거하지 않는다. Last, Bid/Ask, L2 및 일일 통계 이벤트의 의미를 구별한다. Replay 디코더의 성공은 거래 세션 완전성의 증거가 아니다.

## 전략 비교

1. 기준 코드 `a7869a8`의 OR 돌파·OR 리테스트·IB 실패돌파 규칙을 먼저 재현한다. 입력 포맷 변경과 전략 변경은 별도 커밋으로 관리한다.
2. 기존 Yahoo 가격에 마이크로 계약가치를 적용한 대리 결과와 실제 NQ/GC 및 MNQ/MGC 결과를 구분한다. 동일 기간의 차이를 먼저 설명한다.
3. 수수료와 슬리피지의 기준·스트레스 조건을 함께 보고한다. 주문 종류별 체결, 갭, 같은 봉의 손절·익절 동시 접촉을 명시한다. 호가가 없는 기간에 정밀 체결을 검증했다고 주장하지 않는다.
4. 기존 코드는 5분봉에 의존한다. 30/60분·1000/3000틱·40/100레인지 비교는 각 봉 생성 규칙과 시간 조건을 구현·검증한 후 수행한다. 분봉만으로 틱/레인지 결과를 만들어 대체하지 않는다.
5. 공식 운영 시간과 비용을 확인한 후 최소 진입 횟수, 합산 포지션 한도, 미실현 손익을 포함한 탈락 기준을 통합 계좌 단위로 검증한다. 횟수를 맞추기 위한 임의 거래를 추가하지 않는다.

## 과적합과 채택 판단

- 이미 Yahoo 예비 분석에서 살펴본 8~10월 구간은 독립적인 미사용 검증 구간이 아니다. 원자료로 다시 계산한 결과는 재현·강건성 검사로 표시한다.
- 후보 변경 시 선택한 파라미터뿐 아니라 탐색한 범위, 실패한 후보와 총 실험 횟수를 남긴다. 시간순 워크포워드에서 학습 시점 이후 자료를 선택 과정에 사용하지 않는다.
- 장세별 손익, 거래 수, 손익 집중도, 비용 민감도, 낙폭과 규정 위반 빈도를 함께 비교한다. 하루 Replay는 파이프라인·체결 동작 확인용으로만 사용한다.
- 최근 수익만으로 채택하지 않는다. 규칙을 고정한 뒤 새로 도착하는 데이터 또는 모의 운용 결과를 별도로 누적한다. 10월 28일 자료는 실제 장 종료 후 추가한다.
- 현재 목표는 검증 가능한 연구 결과와 모의 운용 후보 선정이다. 실거래 주문이나 전략 활성화는 이 계획에 포함하지 않는다.
